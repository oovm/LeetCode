# [LFU Cache](https://leetcode.com/problems/lfu-cache/)

## 问题

请设计并实现一个满足**最不经常使用（LFU）**缓存约束的数据结构。

- 构造时给出容量 `capacity`。
- 读取操作的输入是键 `key`：键存在则返回其值并把该键的使用频次加一，不存在返回 `-1`。
- 写入操作的输入是键值对 `key`、`value`：键存在则更新值并把使用频次加一；键不存在则插入，频次记为一。缓存已满时，必须先淘汰**使用频次最小**的键；频次相同时淘汰**最久未被使用**的那个。

读取与写入都必须以 $O(1)$ 的平均时间复杂度运行。

**示例 1**

- **输入**：`["LFUCache", "put", "put", "get", "put", "get", "get", "put", "get", "get", "get"]`，`[[2], [1, 1], [2, 2], [1], [3, 3], [2], [3], [4, 4], [1], [3], [4]]`
- **输出**：`[null, null, null, 1, null, -1, 3, null, -1, 3, 4]`
- **解释**：容量为 2。写入 `(1, 1)`、`(2, 2)` 后键 1 与键 2 的频次都是 1。读取键 1 后频次变为 2。写入 `(3, 3)` 时，频次最小的键是键 2，淘汰它。读取键 2 返回 `-1`，读取键 3 返回 3，键 3 频次变为 2。写入 `(4, 4)` 时，键 1 与键 3 频次相同，淘汰更久未使用的键 1。之后读取键 1 返回 `-1`，读取键 3 与键 4 分别返回 3 与 4。

**示例 2**

- **输入**：`["LFUCache", "put", "get", "put", "get", "get"]`，`[[2], [1, 1], [1], [2, 2], [3], [2]]`
- **输出**：`[null, null, 1, null, -1, 2]`
- **解释**：容量为 2。键 1 被读取后频次为 2，键 2 频次为 1。读取不存在的键 3 返回 `-1`，读取键 2 返回 2。

**约束**

- $0 \le \texttt{capacity} \le 10^4$
- $0 \le \texttt{key} \le 10^5$
- $0 \le \texttt{value} \le 10^9$
- 读取与写入的调用次数至多为 $2 \times 10^5$

## 解答

### 朴素想法：淘汰时全表扫描

维护「键 → 值」与「键 → 频次」，需要淘汰时扫描所有键，取频次最小且最久未使用者。正确，但每次淘汰是 $O(n)$。

### 两个维度的排序键

LFU 的淘汰顺序由「频次升序、同频次内使用时间升序」决定。它是一个**双关键字**顺序，单纯按频次分组还不够——同频次编号内部仍要维持使用顺序。

### 频次桶加桶内双向链表

为每个频次维护一个桶，桶内是一条按使用时间排列的双向链表：头部是最近使用，尾部是桶内最久未使用。另用一个全局的最小频次记录当前最小非空桶。

- 命中键时：把节点从其频次桶摘下，接到频次加一的桶头部。
- 桶被摘空时：若它正是最小频次桶，最小频次加一。
- 淘汰时：最小频次桶的尾节点就是牺牲者。
- 插入新键时：接到频次一的桶头部，并把最小频次重置为一。

哈希表负责「键 → 节点」的定位，桶内链表负责使用顺序，最小频次负责定位淘汰桶，三者合起来让每次操作只碰常数个节点。

### 最终算法

读取：键不存在返回 `-1`；存在则摘下节点、接入频次加一的桶，返回其值。

写入：容量为零时直接返回。键已存在则更新值并做与读取相同的频次迁移。键不存在时，若已满则摘除最小频次桶的尾节点并从哈希表删除该键；随后新建节点接入频次一的桶。

## 复杂度分析

### 时间复杂度

每次读取与写入均为 $O(1)$。

哈希表定位、桶内摘除与头插都只改动常数个指针；最小频次只在桶被摘空时加一，因此不需要全表扫描。

### 空间复杂度

$O(\texttt{capacity})$。

每个键对应一个节点，节点由一个频次桶持有；桶的头部与尾部索引数量不超过节点数。
