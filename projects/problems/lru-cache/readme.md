# [LRU Cache](https://leetcode.com/problems/lru-cache/)

## 问题

请设计并实现一个满足**最近最少使用（LRU）**缓存约束的数据结构。

- 构造时给出正整数容量 `capacity`。
- 读取操作的输入是键 `key`：键存在则返回值，不存在返回 `-1`。
- 写入操作的输入是键值对 `key`、`value`：键存在则更新其值，否则插入。若插入时缓存已满，必须先淘汰**最久未被读取或写入**的键，再插入新键。

读取与写入都必须以 $O(1)$ 的平均时间复杂度运行。

**示例 1**

- **输入**：`["LRUCache", "put", "put", "get", "put", "get", "put", "get", "get", "get"]`，`[[2], [1, 1], [2, 2], [1], [3, 3], [2], [4, 4], [1], [3], [4]]`
- **输出**：`[null, null, null, 1, null, -1, null, -1, 3, 4]`
- **解释**：容量为 2。写入 `(1, 1)`、`(2, 2)` 后读取键 1 得到 1，键 1 成为最近使用。写入 `(3, 3)` 时淘汰键 2。随后读取键 2 返回 `-1`。写入 `(4, 4)` 时淘汰键 1。最后读取键 1 返回 `-1`，读取键 3 与键 4 分别返回 3 与 4。

**示例 2**

- **输入**：`["LRUCache", "put", "get", "put", "get"]`，`[[1], [2, 1], [2], [3, 2], [2]]`
- **输出**：`[null, null, 1, null, -1]`
- **解释**：容量为 1。写入 `(2, 1)` 后读取键 2 得到 1。写入 `(3, 2)` 时淘汰键 2，再次读取键 2 返回 `-1`。

**约束**

- $1 \le \texttt{capacity} \le 10^4$
- $0 \le \texttt{key} \le 10^4$
- $0 \le \texttt{value} \le 10^5$
- 读取与写入的调用次数至多为 $2 \times 10^5$

## 解答

### 朴素想法：每次操作都扫描使用顺序

为每个键记录最近一次被读取或写入的时刻，淘汰时扫描全部键取时刻最小者。正确，但每次操作都要 $O(n)$ 扫描，容量大时退化严重。

### 两个相互独立的索引需求

缓存同时要回答两个问题：给定键去哪里找值，以及给定淘汰时机淘汰谁。前者按**键**索引，后者按**最近使用顺序**索引。把这两件事压进一个数组，就会在其中一个维度上退化为线性扫描。

### 哈希表加双向链表

用哈希表完成「键 → 值所在位置」的常数时间定位；用一条双向链表维护使用顺序，头部是最近使用，尾部是最久未使用。命中时把对应节点从原位置摘下并接到头部；写入新键时同样接到头部；超容量时从尾部摘除节点并从哈希表删除其键。摘除与头插只改动常数个指针，因此两个操作都是 $O(1)$。

### 最终算法

- 读取：键不在哈希表则返回 `-1`；否则取出节点，摘下并接到头部，返回其值。
- 写入：键已存在则更新值并把节点接到头部；键不存在时，若已满则先摘除尾节点并从哈希表删除该键，再新建节点接到头部并写入哈希表。

## 复杂度分析

### 时间复杂度

每次读取与写入均为 $O(1)$。

哈希表定位是均摊 $O(1)$；链表摘除与头插只改动常数个指针，不随容量增长。

### 空间复杂度

$O(\texttt{capacity})$。

哈希表与链表节点各保存至多一份容量规模的数据，两者都是线性规模。
