# [Design HashMap](https://leetcode.com/problems/design-hashmap/)

## 问题

请你设计一个**键值映射**，支持以下操作。

- 构造：建立空映射。
- 写入：把键值对写入映射。键已存在时用新值覆盖旧值。
- 读取：键存在则返回对应值，不存在返回 `-1`。
- 删除：键存在则移除该键，不存在时不做任何改变。

**示例 1**

- **输入**：`["MyHashMap", "put", "put", "get", "get", "put", "get", "remove", "get"]`，`[[], [1, 1], [2, 2], [1], [3], [2, 1], [2], [2], [2]]`
- **输出**：`[null, null, null, 1, -1, null, 1, null, -1]`
- **解释**：写入 `(1, 1)` 与 `(2, 2)` 后，读取键 1 得到 1，读取键 3 返回 `-1`。用新值覆盖键 2 后读取得到 1；删除键 2 后再读取返回 `-1`。

**示例 2**

- **输入**：`["MyHashMap", "put", "get", "remove", "get"]`，`[[], [1, 3], [1], [1], [1]]`
- **输出**：`[null, null, 3, null, -1]`
- **解释**：写入 `(1, 3)` 后读取得到 3，删除后读取返回 `-1`。

**约束**

- $0 \le \texttt{key}, \texttt{value} \le 10^6$
- 每个操作调用次数不超过 $10^4$

## 解答

### 朴素想法：线性查找

用两个列表并行保存键和值：写入前扫描键是否已存在，读取与删除同样线性扫描。正确，但每次操作 $O(n)$。

### 直接映射的空间问题

键值都在 $10^6$ 以内，直接用定长数组把键当下标可以做到常数时间。但无论实际写入多少对键值，都要按整个值域占用空间，且「未写入」与「写入零」需要额外的存在标记才能区分。

### 桶数组加链式冲突处理

把键压到较小的桶数组上：由键算出桶下标，每个桶维护若干键值对。写入、读取、删除都只在该桶内比较，桶内条目数是均摊常数，因此平均 $O(1)$。读取命中时返回保存的值，未命中直接返回 `-1`，不需要额外的存在标记数组。

### 最终算法

- 写入：定位桶，桶内已有该键则覆盖其值，否则追加一对键值。
- 读取：定位桶，桶内找到该键则返回其值，否则返回 `-1`。
- 删除：定位桶，桶内找到该键则移除该对键值。

## 复杂度分析

### 时间复杂度

每次操作平均 $O(1)$。

桶下标由键直接算出；桶内条目数在均匀散列下是均摊常数，因此写入、读取、删除都只做常数次比较。

### 空间复杂度

$O(n + B)$，其中 $n$ 是映射内键值对个数，$B$ 是桶数组长度。

桶数组是固定的较小规模，键值对本身只在所属桶内保存一份。
