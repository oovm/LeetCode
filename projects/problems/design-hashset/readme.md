# [Design HashSet](https://leetcode.com/problems/design-hashset/)

## 问题

请你设计一个**不含重复元素**的哈希集合，支持以下操作。

- 构造：建立空集合。
- 加入：把给定键写入集合。键已存在时不做任何改变。
- 删除：把给定键从集合中移除。键不存在时不做任何改变。
- 查询：判断给定键是否在集合中。

**示例 1**

- **输入**：`["MyHashSet", "add", "add", "contains", "contains", "remove", "contains"]`，`[[], [1], [2], [1], [3], [2], [2]]`
- **输出**：`[null, null, null, true, false, null, false]`
- **解释**：加入 1 与 2 后，查询 1 为 `true`，查询 3 为 `false`；删除 2 后再查询 2 为 `false`。

**示例 2**

- **输入**：`["MyHashSet", "add", "add", "remove", "contains"]`，`[[], [5], [5], [5], [5]]`
- **输出**：`[null, null, null, null, false]`
- **解释**：重复加入 5 只保留一份；删除后查询为 `false`。

**约束**

- $0 \le \texttt{key} \le 10^6$
- 每个操作调用次数不超过 $10^4$

## 解答

### 朴素想法：线性查找

用一个列表保存元素：加入前先扫描是否已存在，查询与删除同样线性扫描。正确，但每次操作 $O(n)$。

### 直接映射的空间问题

键的取值范围是 $10^6$，用定长标记数组可以把每次操作压到常数时间，但无论实际加入多少元素都要占用整个值域的空间。集合的规模通常远小于值域，直接映射不划算。

### 桶数组加链式冲突处理

把值域压到一个较小的桶数组上：由键算出桶下标，每个桶内维护一个元素列表。加入、删除、查询都只在该桶内比较，桶内元素数量是均摊常数，因此平均 $O(1)$。键范围固定为 $10^6$，按质数取模可以保持较好的散列分布。

### 最终算法

- 加入：定位桶，桶内已有该键则返回，否则追加。
- 删除：定位桶，桶内找到该键则移除。
- 查询：定位桶，桶内线性比较是否命中。

## 复杂度分析

### 时间复杂度

每次操作平均 $O(1)$。

桶下标由键直接算出；桶内元素数在均匀散列下是均摊常数，因此加入、删除、查询都只做常数次比较。

### 空间复杂度

$O(n + B)$，其中 $n$ 是集合内元素个数，$B$ 是桶数组长度。

桶数组是固定的较小规模，元素本身只在所属桶内保存一份。
