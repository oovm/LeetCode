# [Min Stack](https://leetcode.com/problems/min-stack/)

## 问题

请你设计一个支持入栈、出栈、读取栈顶与**读取栈内最小值**的栈，并且所有操作都必须在 $O(1)$ 时间内完成。

- 构造：建立空栈。
- 入栈：把给定值压入栈顶。
- 出栈：弹出栈顶元素。题目保证栈非空时才会调用。
- 读栈顶：返回当前栈顶元素。题目保证栈非空时才会调用。
- 读最小值：返回当前栈内最小元素。题目保证栈非空时才会调用。

**示例 1**

- **输入**：`["MinStack", "push", "push", "push", "getMin", "pop", "top", "getMin"]`，`[[], [-2], [0], [-3], [], [], [], []]`
- **输出**：`[null, null, null, null, -3, null, 0, -2]`
- **解释**：依次压入 `-2`、`0`、`-3` 后最小值为 `-3`。弹栈一次后栈顶是 `0`，此时最小值为 `-2`。

**示例 2**

- **输入**：`["MinStack", "push", "push", "getMin", "pop", "getMin", "top"]`，`[[], [0], [2], [], [], [], []]`
- **输出**：`[null, null, null, 0, null, 0, 0]`
- **解释**：压入 `0` 与 `2` 后最小值为 `0`。弹栈后最小值仍为 `0`，栈顶也是 `0`。

**约束**

- $-2^{31} \le \texttt{val} \le 2^{31} - 1$
- 每个操作调用次数不超过 $3 \times 10^4$
- 读栈顶、读最小值、出栈只在栈非空时调用

## 解答

### 朴素想法：每次读最小值都扫全栈

栈本身用一条序列保存，读最小值时遍历全部元素取最小。正确，但读最小值是 $O(n)$，不满足常数时间要求。

### 最小值随入栈单调变化

栈的弹出顺序是固定的：只有入栈、出栈两种改变。一个元素入栈时，栈内最小值只会变成「原最小值与该元素中的较小者」；出栈时，只要同时恢复上一个状态的最小值即可。也就是说，最小值的历史可以被入栈顺序唯一决定，没必要每次重新计算。

### 辅助最小值序列

用两条并行序列：一条保存元素本身，一条保存「截至当前栈顶的最小值」。入栈时向最小值序列追加「上一个最小值与新值的较小者」；出栈时两条序列同时弹出。读最小值直接取辅助序列的栈顶，只花常数时间。

### 最终算法

- 入栈：元素压入主序列；辅助序列压入「空栈时取新值，否则取辅助栈顶与新值的较小者」。
- 出栈：主序列与辅助序列同时弹出栈顶。
- 读栈顶：返回主序列栈顶。
- 读最小值：返回辅助序列栈顶。

## 复杂度分析

### 时间复杂度

每种操作均为 $O(1)$。

入栈、出栈与两次读取都只访问两条序列的尾部，不随元素数量增长。

### 空间复杂度

$O(n)$，其中 $n$ 是当前栈内元素个数。

主序列保存全部元素，辅助序列为每个元素保存一份当时的最小值，两者都是线性规模。
